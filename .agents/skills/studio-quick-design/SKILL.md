# 快速设计

1. 把需求归为数值调整、已有规则改动或小型新机制。阅读相关设计、当前脚本和 Resource，确定本次变化相对当前实现的差异。
2. 写清玩家可见的变化、适用条件、受影响的系统和最小范围。数值调整写出原值、目标值、单位和配置位置。规则改动写出触发、消耗、结果和边界条件。新机制先切出一段能玩、能验收的流程。
3. 用游戏中可观察的结果定义验收。涉及日推进、经济、门客或存档时，覆盖受影响的旧数据和边界情况。写清与既有设计的冲突以及需要玩家确认的体验判断。
4. 输出可交给 `studio-dev-story` 的故事摘要。需要落盘时更新对应设计文档，沿用 [故事模板](../studio-dev-story/references/story.md) 记录实现范围和验收。
