# 接手现有项目

1. 从仓库根目录读取 `project.yaml`、`project.godot`、`git status --short` 和最近的提交。用 `engine.code_root` 定位脚本，按 `run/main_scene` 找到启动场景。
2. 读取 `docs/game_design/01_游戏总览.md` 的体验支柱和核心循环，再按需核对相关设计、当前脚本和重构清单。区分已观察到的行为、代码中存在但未运行的行为、设计中的目标，以及进行中的改动。
3. 需要确认启动基线时，按同级 `studio-smoke-check/SKILL.md` 检查，并记录引擎版本、结果和缺少的验证。
4. 给出一个优先级最高、能在游戏里验收的下一步，以及可观察的完成条件。优先处理妨碍现有核心循环或正在进行的重构验收的问题。轻量模式用一条故事记录需求和验收即可。

盘点以报告为交付。用户已有明确的实现请求时，按 `studio-dev-story` 继续该范围内的工作。
