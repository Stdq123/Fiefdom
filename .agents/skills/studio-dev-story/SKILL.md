# 实现一条故事

1. 用用户请求或故事文件确定范围。核对现有工作区改动、相关设计和实现入口。口头任务可在当前会话里按 [故事模板](references/story.md) 明确玩家行为、边界和验收条件。
2. 沿用现有脚本、信号和 Resource，完成一条能从正常场景入口触发的玩法或修复。用户授权的行为变更同步到相关设计。仅在用户要求分工时按领域调用 `.codex/agents/` 中的角色。
3. 按同级 `studio-smoke-check/SKILL.md` 运行 Godot 检查。用相关场景、现有测试或明确的手动步骤逐项核对验收条件。涉及 UI 时覆盖实际布局和交互，涉及手感时记录试玩反馈。
4. 汇总改动文件、证据和剩余验证。遇到失败时，区分本次改动造成的问题和复现于基线的问题。按 `studio-story-done` 复核验收后再标记完成。
